# 2026-07-17 — Nachtarbeit: Abstention B/C Notification Pipeline

## Was ich gemacht habe

### Gap: Reason B/C Enthaltungen — kein Owner-Notification

Die Architektur war stark, aber ein Loch: Wenn ein User Enthaltung mit Grund B ("Mehr Infos") 
oder C ("Klärung") wählt, wurde der Abstention-Record in Strapi gespeichert — aber der 
Project Owner/Einreicher bekam keine Nachricht. Der CONCEPT.md sah einen klaren 
Folgeprozess vor: Anfrage → Owner antwortet → User wird erneut eingeladen.

**Flow:**
User wählt B/C → `AbstainReasonModal` → `createAbstention()` → Strapi Abstention Record

→ **Fehlte:** Owner-Benachrichtigung.

### Lösung: info-request Endpoint + Teams Webhook

**Backend:**
- `abstention controller`: neue `createInfoRequest()` action
  - Speichert Abstention mit B/C reason
  - Lädt Round → Project → Owner
  - Sendet Teams-Webhook-Notification (user, typ, detail, owner)
  - Audit-Log-Eintrag pro Info-Request
  - Graceful fallback wenn Teams-Webhook nicht konfiguriert
- Neue Route: `POST /abstentions/:roundId/info-request`
- `teamsWebhook.ts`: erweitert um `notifyAbstentionRequest()` für B/C Typen
  - Farbe: Orange (FF8C00) für Info/Klärung
  - Titel: "📚 Info-Anfrage" / "🤔 Klärungsbedarf"

**Frontend:**
- `strapi.ts`: `createAbstention()` routet B/C automatisch zum info-request Endpoint

**Landing Page:**
- Neue FAQ: "Was passiert, wenn jemand 'Mehr Infos nötig' wählt — und dann?"
  - Erklärt den kompletten B/C Workflow für Besucher
